# Names for functions of the vanilla iwd2.exe that src/ does not define yet.
# make_project.py applies them below our src/ names and above IEex's. One
# "0xADDR NAME" per line; the comment above each line says how the function
# was identified (objdump of the vanilla exe, the Ghidra decompilation, and
# docs/evidence/<ADDR>.md).

# IEex calls it CGameSprite_Hit. It rolls the attack d20 with
# CUtil::UtilRandInt(20, luck) + 1 (0x73BA6D), adds the attack bonus
# (CRuleTables::sub_546B60 and 0x547020) and compares it with the target's AC
# (CGameSprite::GetAC 0x723CC0); a natural 20 hits, and a second d20 confirms
# a critical. Its asserts name nAttackCount, curWeapon, curAttack and target.
# Evidence: 73B760.md.
0x73B760 CGameSprite::Hit

# IEex calls it CGameSprite_Damage. It rolls the weapon's (and launcher's)
# damage dice with CUtil::UtilRandInt(ability dice size, luck) + 1, once per
# die (0x73D6DE, 0x73D745), adds the strength modifier
# (CRuleTables::GetAbilityScoreModifier) and builds the damage effect.
# Evidence: 73D560.md.
0x73D560 CGameSprite::Damage

# Unnamed (FUN_00547020). max(0, nBonus - nStep * nAttack): CGameSprite::Hit
# calls it (0x73BB8A) with the base attack bonus and step CRuleTables::
# sub_546B60 returned and the attack's index in the round (nAttackCount - 1);
# CScreenCharacter::UpdateEquipmentInformation calls it for the record
# screen's attack bonus list. ecx (a CRuleTables) is set by every caller but
# not read. Evidence: 547020.md.
0x547020 CRuleTables::GetIterativeAttackBonus
