**Behaviour of `resolve_probe`:**
1. Load `<repo>/docs/wso/probe-list.json`; no file or no entry whose address matches by `_addr_key` → exit 2, `0x716E80 is not on the probe list`.
2. The entry's `batch` must exist in the state → else exit 2.
3. Refuse (exit 1) a `fork` or `neither` side whose `deciding_kind(case)` is `dump reading`, with the same wording the close uses ("a fork/neither verdict decided by a dump reading ...").
4. Refuse (exit 1) when `<repo>/docs/evidence/<ADDR>.md` is missing or has no line containing one of `EVIDENCE_PHRASES` that ends with `case <case> decides` (the same check `close` applies to a batch's rows; reuse it).
5. Rebuild the row from `docs/wso/disagreements.json` by address, with the same fields `next` gives batch rows; append it to the batch's `rows` unless an entry with that address is already there; record the verdict exactly as `verdict` does (`side`, `case`, `losing_kind` derived the same way, `measured: "none"`).
6. Remove the entry from the probe list and write both files atomically (temp file + `os.replace`, as the other writers). An emptied probe list is written as `[]`.
7. Print `resolved 0x716E80 in b011: ours (case dump-716E80); probe list now 0 entries`.

**What a probe is here** (ruled; do not re-litigate): per row the cheapest DECISIVE check of the body's behaviour against the original, one of
- a replay checkpoint of an EXISTING capture under `/home/thier/iwd2r-runs/` (FF `m3-end-first_fight-a-20261017-183441`, SL `m3-end-save_load-b-20261017-183641`, `m3-end-walk_and_talk-a-20261017-183043`, `m3-end-world_entry-a-20261017-182652`, and any chargen capture you find there), our tree replayed headless against the capture's `original/` side, with engine shots cropped and pixel-compared where the body draws;
- a new Windows Sandbox `replay compare` of an existing `scenarios/*.txt` (not `pending/`) when no capture exercises the row (chargen rows: `scenarios/chargen_replay.txt`), within the launch limit;
- a function-oracle case (`oracle/cases/`, run with `tools/oracle.py run`) when the body is callable with crafted inputs;
- an explicit PARK with the would-decide condition (which capture or case would decide it) when none of the above can exercise the body: a parked row is an acceptable outcome, a fabricated or non-decisive probe is not.

A verdict is confirmed (`match`) when the checkpoint or case that exercises the body agrees between the original and ours. It flips (`flip`) when ours diverges from the original at a point the body decides and the fork's body (read with `git show` at the pinned sha) would not. A `flip` is REPORTED in the note and the report; `src/` and `docs/wso/wave-state.json` are never changed by this task.

**Recording (binding format):** one prose paragraph in the row's evidence file Notes section, starting `Rule-3 audit probe (2026-10-23):`, stating the probe kind, the run id or replay + checkpoint name (or the oracle case id and run folder), the inputs (or input count and generation rule), the result (N/N matched, or the exact divergence with file:line), and one line tying it to the verdict (`ours` confirmed: the original and ours agree at ..., the fork's body would ...). No new front-matter field.
