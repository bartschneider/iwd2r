## Notes

The original's body is one instruction, `jmp 0x790B70`
(CChitin::SynchronousUpdate; objdump `E9 BB AB 36 00` at 0x425FB0, NOP
padding to 0x425FC0). It is slot 0 of CBaldurChitin's vtable (0x847F90), which
CChitin::WinMain calls once per frame (`call [edx]` at 0x79284B).

Ours calls `platform::replay::OnFrame()` before CChitin::SynchronousUpdate.
That is the replay recorder's frame hook in the original
(oracle/replay/recorder.cpp patches this same jmp to its FrameTrampoline,
vanilla.json `frame_hook`), so both sides count a frame, run the scenario
step, write the dumps and advance the virtual clock at the same point. OnFrame
returns at once unless IWD2R_STATE_DUMP is set (platform/replay.h), so
outside the replay mode the function does what the original's does.

Ours calls `platform::replay::OnFrameEnd()` after CChitin::SynchronousUpdate
returns. The recorder's FrameTrampoline does the same: it calls 0x790B70
itself (a thiscall with no arguments that ends in a plain `ret`, at 0x790CC3,
0x790D87 and 0x790DDE) and then calls its OnFrameEnd before returning to
WinMain. OnFrameEnd fires the frame's due timers, which wake the AI thread,
so on both sides the AI update of a frame runs after the main thread's frame,
as long as the frame takes less real time than the AI thread's 100 ms wait
(MainAIThread's WaitForSingleObject, push 0x64 at 0x4244D8). OnFrameEnd first
counts a frame where that did not hold (au_counter moved since the frame
began, or an update in progress) in the dump's ai_overlap_frames, which
tools/oracle.py fails at a checkpoint.
Before, the timers fired at the start of the frame, and the AI update raced
the main thread's render for the visible area's list lock (field_214, taken
by CGameArea::Render 0x477740 through CInfGame::BeginListManipulation
0x59F9A0 and by CGameArea::SortLists 0x4794E0 at the start of
CGameArea::AIUpdate 0x46E3D0). The winner decided whether the AI update of
the frame that starts the world timer saw m_firstRender (BYTE 0x3DA) at 1 or
0 (task-frame-order report, platform/replay_clock.h "The order inside a
frame"). OnFrameEnd is a no-op outside the replay mode and after a call the
frame gate held.

No oracle case: there is nothing to compare beyond the call it forwards to.
`tools/oracle.py replay compare` exercises the hook on both sides at every
frame.
