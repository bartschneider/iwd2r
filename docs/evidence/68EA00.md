## Notes

Ghidra's label is IEex's CScreenWorld_StartDialog; ours is CScreenWorld::StartDialog(CGameSprite* pCharacter, CGameSprite* pTarget, BOOLEAN bPlayerInitiated, BOOLEAN bInteraction) (`ret 0x10`). pCharacter is the party member spoken to (dialog tokens, the player's name and colour, the portrait), pTarget the speaker whose DLG is loaded: m_dialog, or field_56E4 when bInteraction. CGameSprite::Dialog (0x752DD0, the ai-dispatch stream's action) calls it with (the action's target, this, 0, 0): a script's Dialog([PC]) on area entry starts Hedron's opening conversation this way, as the player's click does through PlayerDialog (0x7537A0).

A hostile speaker (EA >= EA_EVILCUTOFF) refuses only when bPlayerInitiated and not bInteraction. Every party member gets CMessage101(FALSE, .., TRUE), CMessageDropPath, DropSearchRequest and ClearActions(TRUE); the speaker and the character turn to each other (CMessageSetDirection) unless asleep (STATE_SLEEPING, SEQ_SLEEP). The dialog panel (GetPanel_21_7) replaces the others, the dialog display takes over the text (CopyDisplay), the viewport shrinks to stru_8E7958 (SetNewViewSize, inlined), the game pauses (m_bPaused, StopTime) and the input mode becomes 0x502 (0x182 when another player controls the dialog). The view position and area (field_F12, field_F1A, read back by EndDialog) are new CScreenWorld fields.

CMessageEnterDialogMode (BROADCAST_FORCED_OTHERS) and CMessageLoadDialog (BROADCAST_FORCED, runs locally and loads the same file again with the same ids) are new message classes. The multiplayer fields (m_bDialogRequestPending and the host's permitted-dialog state) are set as in the original; single player never reads them.

When CGameDialogSprite::StartDialog finds no start condition that holds, the two blank lines are removed, the display's top string restored and EndDialog(FALSE, FALSE) closes the panel again.
