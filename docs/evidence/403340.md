## Notes

`src/C2DArray.cpp` matches the decompilation. Both upper-case copies of the
two labels, look for the first column label equal to `nX` and then for a row
label equal to `nY`, and return that cell or `m_default`. The original stops
at the first matching column: if `nY` is missing it returns the default, and
ours goes on to the next column. Ours can only find a row there that the first
match did not find, and the row search does not depend on the column, so the
result is the same.

Calling convention (objdump): `__thiscall`, `ret 8` at 0x4033F5, returns
`const CString&` in eax, with no hidden return pointer.

Oracle case `tables/getat_labels` (oracle/cases/tables.cpp). The tables are
the game's XPLEVEL.2DA (extracted from the vanilla copy by tools/bif.py) and
three synthetic texts. "signed" has signs, overflow, a short row, a label-only
row and an over-long row. "labels" has duplicate and lower-case labels, an
empty row label, a blank line and LF line ends. "empty" has a default only.
Our tables come from `C2DArray::LoadText`. The original's C2DArray, whose
constructor is inlined everywhere, is a zeroed 0x24-byte block from its
operator new (0x7FC95B), filled with the same labels, cells and default
through its CString(LPCSTR) constructor (0x7FCC88). The lookups use every pair
of lookup words: each label in upper and lower case, plus "", "NOPE", " A", "A
", "ROW1\r", "1 " and "-1". Then come 10,000 random pairs per table, with each
letter's case flipped at random. The case compares the returned string's
position (which cell, or the default) and its text.

Result: runs 20261012-225526 (seed 1, iterations 10000) and 20261012-225535
(seed 7) passed, each with 45,300 inputs, 0 failures. No change to ours.

Not compared: bytes past 0x7F. The original's MakeUpper (0x7FD0F0) is the
CRT's `_mbsupr` (0x7EB13E), which upper-cases through the multibyte tables
`_setmbcp` built from the system's ANSI code page: on code page 1252, 0xE9
becomes 0xC9, and on a double-byte code page lead bytes go through
LCMapString. Ours (compat `CString::MakeUpper`) upper-cases ASCII only. A
first run with a "caf\xE9" label failed 309 inputs this way: the original
returned the default where ours found the cell. The game's tables are ASCII,
and the original's result depends on the machine's code page, so ours is
unchanged and the case uses ASCII text only.
