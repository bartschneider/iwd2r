## Notes

- **The bytes.** `0x8AB8A4` is in `.data` (RVA and raw offset both `0x4A5000`), so its file offset is `0x4AB8A4`; the bytes there are `5c 00 00 00 5c 76 61 6c ...` — a NUL-terminated one-character string `"\"`, not `";"`. Both append sites push exactly that address: `0x78190D` and `0x781971` are `68 a4 b8 8a 00` (`push 0x8AB8A4`) followed by `call 0x7FCFAA`, the `CString::operator+=(const char*)` overload (it calls `KERNEL32!lstrlenA`), not the char overload `0x7FCFD1` at `0x78187C`. That is why the source keeps the string literal `"\\"` rather than `'\\'`.
- **The `0x3B`.** The only `0x3B` byte in the function is `push 0x3b` at `0x7818E5`, the argument to `CString::Find(';')`; the decompiler's `temp += ";"` is most likely a misread of it.
- **The guards.** Both appends sit behind `cmp byte ptr [ecx + eax - 0x1], 0x5c` (`0x781906`, `0x78196A`), i.e. `if (temp.GetAt(temp.GetLength() - 1) != '\\')`.
- **History.** The literal has been `";"` since upstream commit `465b0c15` (Batalov, 2022-11-26) added the file; it was never edited afterwards.
- **The symptom.** The GOG `icewind2.ini` holds `HD0:=C:\GOG Games\Icewind Dale II` with no trailing backslash, so the value took the append branch and became `...Icewind Dale II;`; `CAliasList::ResolveFileName` then built `...Icewind Dale II;data\GUIfont.bif`, the file never opened, and the stubbed `CDimm::CDSwitch` quit at the start screen with `no drive holds data\GUIfont.bif (drives 0x1); the CD request is not ported, quitting`.
- **The marker.** `// #binary-identical` above the function is left in place: the repo has no marker for "fixed but not measured" (only `#binary-identical` and `#not-binary-identical`, and the latter means known to differ), and the function still differs in length from the fork's recovery (`docs/wso/disagreements.json`: 526 against 539).
- **Out of scope.** `CAliasList::ResolveFileName` (0x781AC0) is not changed here; its unconditional `return TRUE` and the parked `world_entry` `ret` mismatch are a separate issue.
