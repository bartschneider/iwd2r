## Notes

- **The loop** walks `MAX_CHARACTERS` slots of `CInfGame::m_characters` (the
  straggler is `CGameObjectArray::INVALID_INDEX`). A character leaves when it
  animates and stands in an area other than the one named by `sAreaName`
  (0x69470E-0x69473F); `bControlledByLocalPlayer` is TRUE without a service
  provider, else it compares the local player id with the sprite's remote
  player id. When the character leaves and the local player does not control
  it, control is handed over (0x6947A4) before the deny, and the sprite gets
  the control-seizure feedback, a full last-update, and a fresh
  `LEAVEAREALUA` action with `m_specificID2 = 1` (0x6947DD-0x694929).
- **The visible-area dance** (0x69492F-0x694A00) happens only when the visible
  area has no characters left: `UnselectAll`, clear the pick and the tooltip,
  deactivate it, move `m_visibleArea` to the sprite's target area
  (`m_pArea->m_id`) and activate that. The original re-reads `GetVisibleArea()`
  at every step (the calls may change it); the port does the same.
- **Two parameters are dead**: `nDirection` and `sParchment` are never read
  (only their by-value copies are destroyed, 0x694A92/0x694AA5); the port keeps
  the signature.
- **The inlined constructor** is the 0x5BC220 one,
  `CAIAction(SHORT, const CString&, CPoint, LONG, LONG)`: it creates and
  destroys a temporary `CAIAction` (0x694877/0x69488B, the quirk that
  constructor documents), assigns the area name through `SetString1`
  (0x6948B4), zeroes `m_specificID` (the 0 argument), `m_specificID3` and
  `m_internalFlags`, and sets `m_specificID2 = 1` (0x6948D5-0x6948F3). The
  port calls it as `CAIAction(LEAVEAREALUA, sAreaName, ptLocation, 0, 1)`.
- **No oracle and no unit test**: the path needs a live hosting session with a
  party split across areas, the object array's share/deny states and the
  sprite's action queue. A fixture would have to fake every call the function
  makes, pinning nothing the read-only disassembly does not already fix. None
  of the replay scenarios drives `m_bLeaveAreaLuaPanicPending`, so there is no
  run to point at either.
