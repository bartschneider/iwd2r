## Notes

Ours had no Render override: the vtable slot fell back to CGameAnimationType::Render 0x55D170, which draws nothing, so animation IDs 0x1200-0x1FFF (in the game data only 0x1201, the black dragon MDR2 of 60GUARDI.CRE) were invisible.

Read from the disassembly (parameters at [esp+0x90] after sub esp,0x7C and four pushes):

- rectFX, ptReference and rGCBounds are not read. A world rectangle is built from the infinity: (nCurrentX 0x90, nCurrentY 0x94) and the size of rViewPort (0x48..0x54), stored at [esp+0x4C].
- Flags: MIRROR_FX when m_currentBamDirection (0x444) > m_extendDirectionTest (0x7F4); always FXPREP_COPYFROMBACK | 4; 2 when transparency != 0. No MIRROR_BAM test.
- field_446 set: field_44A's CResBitmap (pRes at +0xA4) is demanded before the loop and released after it (0x77F190); in the loop each drawn quadrant's cell gets its colour table as palette.
- For each of the m_nQuadrants (0x7F5) cells of the m_currentVidCell array (stride 0xDA): its centre and frame size, rFXRect = SetRect(0, 0, cx, cy), pVidMode->GetFXSize(size) (the size is overwritten and not used again), this->CalculateGCBoundsRect(rQuad, ptNewPos, centre, posZ, width, height); IntersectRect with the world rectangle into a temporary that IsRectEmpty tests (CRect operator&): a quadrant off screen is skipped. FXPrep's result is not tested.
- The tint per quadrant cell as in the other Renders (each channel the cell's plus the tint's minus 255, at least 0, red from the low bytes), FXRender(cell, centre, flags, transparency), the tint restored.
- FXRenderClippingPolys gets rQuad itself (0x6B7579 `lea ecx,[esp+0x84]`, the CalculateGCBoundsRect output), not raised by posZ as the other Renders' bounds are.
- FXUnlock at 0x6B75E7: bFadeOut set passes &rFXRect and ptPos + centre; otherwise 0x6B75D6 pushes &CPoint(0, 0) and `eax` (0) as the rectangle (NULL).
- FXBltFrom(nSurface, rFXRect, ptPos, centre, flags).
