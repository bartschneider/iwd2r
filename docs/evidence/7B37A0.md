## Notes

Ported from the Ghidra listing and the disassembly (0x7B37A0-0x7B3B5E, `ret 0x18`): the 24-bit BMP
(three bytes, B then G then R; `nDataJump` bytes skipped after each row) onto a 16-bit surface,
through the mode's channel shifts. `field_C2`/`field_C6`/`field_CA` are the source shifts `8 - the
destination's bit count` and `m_dwRBitShift`/`m_dwGBitShift`/`m_dwBBitShift` the destination shifts
(both set by `CVidInf::ParsePixelFormat`, `src/CVidInf.cpp:2479`), so the same code serves 5-6-5 and
5-5-5 - the oracle case runs both. `lPitch` is in **bytes** and the rows go bottom-up (`pSurface +=
-bmpSize.cx - lPitch / 2` per row, as `BltBmp24To32` does with `lPitch / 4`).

Two forms, selected by bit 0 of `dwFlags`:

- plain: each source pixel becomes `(B >> srcB) << dstB | (G >> srcG) << dstG | (R >> srcR) << dstR`.
  The original writes the row as 16-bit pairs where the width allows and peels the single pixel of a
  width below two; the port writes one pixel at a time (identical values, the 32-bit sibling's
  shape) and keeps one quirk: the single-pixel path is a do-while, so **a zero-width blit still
  writes one pixel and consumes one source pixel per row** (0x7B3940; NOTE in the code, exercised by
  the case's width 0).
- keyed (0x1): pure green (`0, 255, 0`) is transparent - the destination keeps its pixel; with 0x4
  a pure black source pixel writes half the destination's channel, read back through the
  destination's mask and shift (`((pixel & mask) >> dstShift) << srcShift >> 1`), the 16-bit
  equivalent of `BltBmp24To32`'s 50% alpha. A black pixel without 0x4 is written as black (only the
  green key is skipped).

The original's pair writes for even widths and its peeled first pixel for odd widths are what the
compiled source does; per-pixel writes store the same values, and the oracle case sweeps widths 0,
1, 2..32 (both parities) to keep the row ends honest.
