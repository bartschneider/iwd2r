## Notes

The 24-bit to 32-bit bitmap blitter with tint, add (brightness) and light
(gamma) applied, which CVidBitmap::RenderDirect (0x7B3190) picks when
CVidMode::ApplyBrightnessContrast(RGB(128,128,128)) is not grey: any
non-zero Brightness Correction or Gamma Correction. The vanilla
icewind2.ini has `Gamma Correction=2`, so every portrait (Character
Generation's Appearance step, CUIControlButtonCharGenAppearancePortrait
0x61D120) goes through it. Ours returned FALSE (a TODO stub), and the
portrait's `UTIL_ASSERT(bResult)` (InfScreenCreateChar.cpp line 13582) then
aborted the engine with SIGSEGV after the Gender step. Found by
scenarios/chargen_replay.txt.

Ported from the disassembly (objdump 0x7CD870-0x7CDCFA), not only from
Ghidra:

- The factors come from CVidImage's three helpers 0x7B4230 (tint), 0x7B4600
  (add) and 0x7B4800 (light), called with `this` and dwFlags; the light
  factors start at `1 << CVidPalette::LIGHT_SCALE` (the byte at 0x85E856,
  3), the tint at 255 and the add at 1.
- dwFlags bit 0 (transparency): pure green (0,255,0) is skipped; with bit 2
  a black pixel becomes a half-black shadow over the destination (alpha
  from the byte at 0x85E6F2, 0x80) mixed with ApplyBrightnessContrast(0);
  other pixels get alpha 0xFF, the tint (signed `sar`), the add, and the
  light clamped to 255, and a result of pure green is moved to (0,254,0).
- Without bit 0 the loop is inline assembly on whole registers (0x7CDC17):
  the add step flips only the low byte (`not al`), the light step shifts by
  a literal 3 and clamps only the low byte (`test ah,0xff` / `mov al,0xff`),
  so higher bits reach the pixel; no alpha.
- Bit 19 (0x80000) turns the pixel grey: (r + g + b) / 4.
- Rows: the surface pointer goes back lPitch + 4 * width bytes after each
  row (the caller starts at the bottom row), the data pointer forward by
  nDataJump.

The original runs both loops as do-while; ours uses for loops, the same for
the non-empty sizes RenderDirect passes (it returns early on an empty
clip).

No oracle case: it writes into a locked surface of the running video mode
(g_pChitin's active engine's CVidMode for the bit shifts and the
corrections). `oracle.py replay compare scenarios/chargen_replay.txt` goes
through it in both engines from the Appearance step on.
