## Notes

Ported from the disassembly (0x5BAD70-0x5BB5F7). In order:

- The character id (inlined `GetCharacterId`), errorCode -1; a slot outside 18 .. 18 + `CScreenInventory::PERSONAL_INVENTORY_SIZE` (the WORD at 0x855128) other than 0x7FFF gives 9374 ("Bad Slot Number"); a failed GetDeny 9373 ("No Sprite"), both returning FALSE.
- A client with a session that is not the sprite's controller and not answering the server asks the server through 0x431560 and returns its answer (0x5BAE39-0x5BAEBC); not ported (ADR 0002), unreachable without a session.
- An item dropped on a bag (slot item of type 58): `AddItemToBag` (0x5C7B10) with the bag's resref; a non-zero count either lowers the hand's stack by it (a stackable item whose count differs) or sends the hand item to the disposable list (`AddDisposableItem`, inlined at 0x5BAF4F) and empties the hand; then `UpdatePersonalItemStatus` (engine vtable +0xEC), the equipment message in a session (`CMessageSpriteEquipment`, 0x50B510, only when connected) and TRUE. A zero count sets the result FALSE and goes on with the slot.
- Otherwise, with auto-stacking and a stackable item in hand, slots 18 .. 41 are searched for a stack of the same resref (8 raw bytes) and identification bit (m_flags & 1) with room: one that takes the whole hand becomes the slot; a smaller room is filled (hand count - max + stack count left in hand).
- Slot 0x7FFF becomes the first empty personal slot, or 17999 ("Inventory Is Full") and FALSE.
- With the result still TRUE: a slot item that is not droppable (file flags & 4 clear) or is marked +0x20 & 0x10 gives 25697 ("This item can not be removed.") and FALSE, skipping the status update. An empty hand on a stack larger than wCount takes wCount into a new `CItem(resref, 0, 0, 0, 0, 0)` with the slot's identification bit (assert line 14884, 0x3A24, wCount != 0); a hand stack onto a matching stack moves min(wCount, hand, room) (assert line 14894, 0x3A2E) and disposes of an emptied hand; anything else swaps hand and slot. Then the status update and the session message.
- Always: `field_562C` = 1, `ProcessEffectList` (0x72DE60), ReleaseDeny.

The remainder of a stack dropped on a bag that is fuller than the stack is lost: `AddItemToBag` cuts the hand stack to what fits before adding it, so the hand's count always equals the count added and the hand item is disposed of (kept, NOTE in 5C7B10).
