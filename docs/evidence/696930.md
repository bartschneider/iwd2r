## Notes

- The empty body **is** the original: C++ emits the base-constructor call the initializer list names
  and the vtable store for the class, which is all 0x696930 contains. The sibling
  `CUIControlScrollBarCharGenSkills` constructor (0x61A2E0) is ported the same way
  (`src/CScreenCreateChar.cpp:7442`, empty body), and its listing is the same two instructions.
- No unit test, and why: the only thing a test could assert about this function is that the vtable
  belongs to the class, which C++ already guarantees at compile time (a `dynamic_cast`/`typeid`
  check would test the type system, not the original). Constructing the object at all needs what
  the *base* constructor demands - a `CUIManager` and `CUIPanel` plus a demanded scrollbar BAM via
  `controlInfo->refBam` - i.e. a new UI fixture for a row that changes no code; no current UI test
  builds a panel or a scrollbar (`grep -n CUIControlScrollBar tests/*.cpp` finds none). The survey
  (report-T80 §2.6) reaches the same conclusion: read-only, no oracle fixture (it would need a real
  panel/manager/scrollbar BAM).
- Proof route if one is ever wanted: a Frida trace of the world container's creation
  (`walk_and_talk` opens the container panel), per survey §2.6.
