## Notes

Two differences from the original fixed, found by vid/realize_range (RealizeRange passes black through it for palette entry 1):

- Brightness: the original complements each channel as a byte (not cl, 0x795E1B) before multiplying by the complemented correction; ours complemented the int, so ~0 was -1 and black came out black at any brightness instead of ~((~b * 255) >> 8).
- Gamma: the scale (1 << LIGHT_SCALE) + correction is an int (0x795E87); ours held it in a BYTE, which wraps for corrections above 247.

The case sweeps every brightness and gamma byte with black and random colours on an original CVidInf from its constructor. The start screen runs with both corrections 0 (smoke hash unchanged).
