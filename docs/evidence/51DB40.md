## Notes

Rewritten from the decompile and the disassembly (0x51DB40-0x51DE12). The pivots are path indexes counted from the goal end: [0] the farthest, [2] the nearest. With a pivot [0] and a stretch longer than 3 nodes on either side of [1], between two points neither on the same row nor column nor on a diagonal: when the stretch has one node per column (|dx| == nodes) the nodes are recomputed along the line with y = ((2 * ay + 1) * dx * sx / 2 + k * dy) / dx * sx (integer idiv, truncating toward zero), one per row likewise for x; each recomputed square must have the snapshot cost `actualCost`, else the smoothing stops. When every node of the stretch is open, they are written back marked -1 (GetPath drops -1 nodes, so the walker goes straight between the pivots) and [1] becomes [0]. The port used different arithmetic, required both signs of dx to equal the node count at once, and never wrote back.

Exemption: called only from BuildPathList inside the search thread; covered with FindPath (see 51D7A0.md).
