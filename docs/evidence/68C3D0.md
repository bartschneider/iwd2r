# 0x68C3D0 CScreenWorld::AsynchronousUpdate

## Why ours was kept

The batch row flags WillScarlettOhara's fork (iwd2-re@e8dd16a750966af53f24daaf49dcb4fb13594c13,
read through git plumbing) as changed against our base body. Diffing his body
against ours shows the only differences are three renames: ``field_EA4``->his ``m_nPopupState``, the ``pGame->sub_5AC0D0()`` call ->his ``UpdateAreaSaveStatus()``, and ``pArea->sub_47A060()`` ->his ``LoadLocalVariables()``..

None of his three names exists in our headers; each denotes the same
address ours names (our stubs keep their address names; his fork renames them
project-wide).

## The exe reading

Bundle decompile: the popup test is ``if (in_ECX[0x3a9] == 0x11)`` -
int index 0x3A9 x4 = +0xEA4, compared to 0x11 = 17, the same field and value
our ``field_EA4 == 17`` reads. The callee list names ``CGameArea::sub_47A060``
as a direct callee, and the CInfGame call ours renders as ``sub_5AC0D0()`` is
the same 0x5AC0D0 target.

Ours already matches the exe; adopting his naming would need header edits
outside this batch's owned files. Kept as ours.
