## Notes

Ported (the import screen's character summary). It loads
characters/<name>.chr through a CResHelper<CResCHR, 1018>, adding a
temporary key for the characters folder when the resource is not found
(CDimm::AddTemporaryKey 0x7823C0, removed again at 0x611190 or 0x61180B).
The original's helper has its own GetData (0x720480) and GetDataSize
(0x720490), the same code as CCreatureFile's (0x7123B0, 0x7123C0); src/ has
no such class, so both are inlined. A file starting "CHR V2.2" (0x8A6478)
builds a CGameSprite from the creature inside it (offset at 0x28, length at
0x2C, the 0x224-byte header asserted at lines 6322-6331) with the arguments
pushed at 0x6110F3-0x611113 and prints: the name (the header's when the
creature has none), race, each class with a level (the CLASS and LEVEL
tokens and strref 16480), alignment and the six abilities as "%s: %d
(%+d)" (0x8B38D0), then sets the portrait of panel 0's control 12 and marks
the resource (dwFlags |= 0x100) before releasing its data. Otherwise it
releases the data and shows strref 39695. The original never deletes the
sprite it builds; neither does ours. Exempt from an oracle case: it writes
into a UI text control and needs the resource manager; the world_entry
scenario does not import a character, so nothing compares it yet.
