## Notes

Ported from the decompile and disassembly. Returns TRUE at once when the video mode is fully faded (m_nFade 0). For each 640x480 WED screen section the rGCBounds rectangle touches, each polygon of the section that is not hidden (type bit 2), whose bounds meet rGCBounds and, for a wall (type bit 1), unless dwBlitFlags 0x400, with the object behind its first edge (above a horizontal edge, or on the non-negative side of the edge's cross product), is filled with pVidMode->field_24 into the locked surface: FillConvexPoly for type bit 8, FillPoly otherwise, dithered when bDithered (fill flags 2, else 1), mirrored (4) and flipped (8) from dwBlitFlags 0x10 and 0x20; type bit 4 skips the first two vertices. The clip is rGCBounds moved down by nPosZ, the reference point ptRef + (nPosX, nPosY).

The original's duplicate check (0x5CE6D8) leaves its loop at the first slot that is set and so never finds a polygon; ours keeps it. CVidPoly::FillPoly (0x7C13A0) is ported (oracle case vid/fill_poly), so non-convex polygons draw too. Checked again against the decompile in the M5 render stream (2026-10-15): unchanged. The call after each exit that Ghidra names CBaldurEngine::CheckEnableLeftPanel (0x799CA0) is the CVidPoly destructor (empty).

src/render/api.h lists this function among the unguarded ones: the polygons it fills are the occlusion mask written into the FX surface between FXPrep and FXUnlock, which a backend needs with the FX begin-group and end-group calls (docs/followups.md, FX groups). The polygon list's empty marker is written as 0xFFFFFFFF (the original's -1 in a DWORD).
