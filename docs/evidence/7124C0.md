## Notes

Ported (Task 6). Calling convention (objdump): `__thiscall` with the
equipment in ecx (`lea ecx,[ebp+0x4AD8]` at 0x70B4E0), four stack
arguments: the CCreatureFileEquipment block, the item array (out), the item
count (out), and the sprite Marshal's a5 (`and eax,0xff` at 0x70B4C9).

The block is filled with 0xFF (26 dwords), the selected weapon set to 1000
and its ability to 0. The count is every non-empty slot of the 51, except
with the flag clear the items of type 0x3A, minus one for the fist, which
is never saved; with no other item the function returns with no array. The
slots are written in the original's order: helmet (6), armor (1), shield
(9), gauntlets (5), left ring (7), right ring (8), amulet (0), belt (2),
boots (3), cloak (4), then the 8 weapons (43..), 4 quivers (11..) and 28
misc slots (15..). Each item: its resref, GetUsageCount(0..2) at +0xA,
m_wear (CItem+0x1E) at +8 and m_flags (CItem+0x20) at +0x10.

With the flag clear, an item of type 0x3A is neither counted nor numbered:
at 0x7125D3 `je 0x712643` jumps past the slot counter's increment (`mov
BYTE PTR [esp+0x2c],1` at 0x71263E for the first slot). Fix round 1: ours
had numbered it, which shifted the later slot numbers and failed the final
`nSlot == *nItems` assert.

With the flag clear, an item whose GetFlagsFile() has 0x800 set is counted
and takes a slot number, but nothing is written to its entry and the block
does not point at it (0x7125DD `test ah,0x8; jne 0x71263E` jumps past the
writes to the counter increment). Ours keeps that.

The selected weapon is written as `m_selectedWeapon - 43` when it is not
the fist (10).

No oracle case: needs loaded CItems. Covered by tests/test_cre.cpp through
CGameSprite::Marshal (0x70B2F0).
