## Notes

Calling convention (objdump): `__thiscall`, `ret 4` at 0x5439AB, DWORD in eax.
The BYTE argument is pushed as a dword and masked (`and edx, 0xFF` at
0x54392D).

It gets the class name from GetClassString(5 = FIGHTER, 0) (0x541DA0, which
copies a global CString and does not read `this`). It formats the level with
"%d" (0x8A64C4), looks up `m_tExperienceLevels.GetAt(level, "FIGHTER")` at
this+0x604 (0x403340), and converts with ToNumber (0x7E7B03, VC6 `atol`, see
403440.md). Ours did the same with the C library's `atol`.

Oracle case `tables/next_level_xp` (oracle/cases/tables.cpp). The original
CRuleTables is a zeroed 0x1B58-byte block (CInfGame::m_ruleTables, CInfGame.h)
with only m_tExperienceLevels at 0x604 filled, the way the C2DArray fixtures
are (403340.md). Ours is zeroed storage of sizeof(CRuleTables) with only that
member constructed and filled by `C2DArray::LoadText`. That is all
GetNextLevelXP reads on either side. There are four XP tables: the game's
XPLEVEL.2DA; "signed XP", a lower-case "fighter" row with signs, overflow,
junk and the columns 255, 256, 0 and 01; "short XP", with a FIGHTER row
shorter than its columns and an overflowing default; and "no FIGHTER XP". Each
is tried at every level from 0 to 255 (0, past the table and the byte's top),
then at 10,000 random levels.

First run (20261012-225211, seed 1): FAILED, 41,024 inputs, 10,271 failures,
all from the overflowing cells and default, for example:

    XP table signed XP: GetNextLevelXP(4)  ("2147483648")
      original 2147483648 (0x80000000), ours 2147483647
    XP table signed XP: GetNextLevelXP(6)  ("99999999999")
      original 1215752191, ours 2147483647

The game's own XPLEVEL.2DA matched at every level.

Fix: ours converts with `iwd2r_atol` (compat/msvc_atol.cpp), as GetAtLong
does. After the fix: run 20261012-225526 (seed 1, iterations 10000) passed
with 41,024 inputs and 0 failures, and so did run 20261012-225535 (seed 7).
