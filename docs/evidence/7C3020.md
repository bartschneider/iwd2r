## Notes

Ported from the Ghidra listing and the disassembly (0x7C3020-0x7C313D, `ret 0x18`; was a stub
returning an empty CRect): the composition window's rect for the IME (report-T80.md §2.10). WSO
calls it `CImm::GetCompositionWindowRect`; ours and Ghidra keep the address-derived name in src
(RE004 waiver below). A null `field_13C` (no mosaic) answers an empty rect. Otherwise the mosaic's
size comes from `CVidMosaic::GetSize` (0x7B0BF0, ported; Demands and Releases the resource), the
height is `nFontHeight * 3 + CImm::PADDING.cy * 2` - three lines and the padding above and below,
the 3/3 static at 0xA09FC0 read as the global `DAT_00a09fc4` - clamped down to the mosaic's own
height, and the rect is `(left, top, left + mosaicWidth, top + height)`.

The placement, branch for branch as the original has it: vertically, when the clamped height is
less than the panel's, the rect goes under the panel and the edit (`panel.y + editSize.cy +
edit.y`) unless the edit reaches past the panel with the height (`panelSize.cy < editSize.cy +
edit.y + height`), in which case it goes above the edit's top (`panel.y - height + edit.y`) or, when
the edit starts nearer the panel's top than the height (`edit.y - height < 0`), centres in the
panel (`(panelSize.cy - height) / 2 + panel.y`); when the height is at least the panel's, the top
is the panel's own. Horizontally, when the mosaic is narrower than the panel, the left is the
panel's plus the edit's size and offset (`(panel.x - mosaicWidth) + editSize.cx + edit.x`) when the
edit is wide enough (`(editSize.cx - mosaicWidth) + edit.x >= 0`), else the panel's plus the edit's
x unless the edit starts before the mosaic's end (`panelSize.cx < edit.x + mosaicWidth`), where the
mosaic centres (`(panelSize.cx - mosaicWidth) / 2 + panel.x`); a mosaic at least as wide as the
panel starts at the panel's corner. Every division is on a positive dividend, so the C/2 matches
the `cdq/sub/sar` pairs.

The CRect returns by hidden pointer: the original is __thiscall, so the pointer is the first stack
argument (`[ebp+4]`), and the oracle case calls through a `__thiscall` pointer accordingly (the
int-returning cases' `__fastcall` shape would put it in edx).
