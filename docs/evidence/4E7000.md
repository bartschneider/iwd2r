## Identity and calling convention

A free helper in the original's CGameSprite.cpp, `__thiscall`-style over a
block pointer in `ecx` (the exe passes `CGameSprite + 0xAF8`, so the nine
values it hashes start at `CGameSprite + 0xB00`); Ghidra shows it as
`FUN_004e7000(void)` because the block type is unknown. The port spells it as

points at the first of the nine values.

## Body

Nine iterations: `value = *++p`; `checksum += value * weight`; `weight *=
2`; 32-bit signed multiply and add throughout. The tenth DWORD is never
read (the loop counter starts at 9).

`CGameSprite::ProcessEffectList` (0x72DE60), in the tail region the tree still
carries as `TODO: Incomplete (0x72E759-0x72FB24)`. There the result is
compared with `CGameSprite::field_9D10` (exe +0x9D10, declared in the tree):
