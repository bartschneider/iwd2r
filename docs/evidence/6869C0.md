# 0x6869C0 CScreenWorld::EngineActivated

## Why ours was kept

The batch row flags WillScarlettOhara's fork (iwd2-re@e8dd16a750966af53f24daaf49dcb4fb13594c13,
read through git plumbing) as changed against our base body. Diffing his body
against ours shows the only differences are one added block - a function-local ``static BOOL s_autoLoadResultWritten`` and a call pair ``Iwd2AutoLoad::IsEnabled()`` / ``Iwd2AutoLoad::WriteResult("loaded", "world engine activated")`` after ``field_119D = TRUE;`` - plus a removed blank line..

``Iwd2AutoLoad`` exists nowhere in our tree (grep over src/, include/,
compat/): it is infrastructure of his fork's own test harness, not original
code. Importing the block could not compile here, and it has no exe counterpart
- so unlike the rename rows there is nothing to import even in spirit.

## The exe reading

The bundle decompile of 0x6869C0 has no static flag and no result
write: after the pause block it runs ``WorldEngineActivated`` ->
``*(undefined1 *)(in_ECX + 0x119d) = 1;`` -> cursor setup, matching our body.
The added block is fork tooling absent from the exe.

Ours already matches the exe; adopting his naming would need header edits
outside this batch's owned files. Kept as ours.
