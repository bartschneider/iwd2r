## Reachability: SP, host branch

The first test is `g_pChitin+0x1033 == 1`; `[0x8CF6D8]` is `g_pChitin`
(`CChitin::cNetwork` is at `/* 0952 */`, `CNetwork::m_bIsHost` at `/* 06E1 */`
→ 0x1032 is `m_bConnectionEstablished`, 0x1033 is `m_bIsHost`), i.e.
`CNetwork::GetSessionHosting() == TRUE`. A client returns at once.

Single player does host the null-provider session: `CScreenConnection::
OnNewGameButtonClick` (src/CScreenConnection.cpp:1424) calls
`CNetwork::HostNewSession()` whenever the provider is not modem/TCP/IP — the
null provider in this build — and `HostNewSession` (0x7A6270, src/CNetwork.cpp:
1644) sets `m_bConnectionEstablished = TRUE` and `m_bIsHost = TRUE` before
`CInfGame::NewGame` runs (`src/CScreenConnection.cpp:1444`). `CInfGame::InitGame`
(0x59F540) branches on `GetSessionHosting()` (src/CInfGame.cpp:1016), and
`~CInfGame` only closes the session when the game object is destroyed. So the
guard passes in single-player gameplay and the body runs; only multiplayer
clients (removed under ADR 0002) skip it. Not dead, not MP-only.

This also corrects the part-D survey's "render routine" reading: the helper is
not a CInfinity surface path (no FXBltFrom/FXUnlock/GetHeightOffset calls; its
callees are the CRE/sprite/object-array/animation APIs in 5819B0.md). It is a
host-side creature spawner; in single player the host is the local machine.

## Body

Five calls to the helper with fixed search-grid points and facings, in order:
(0xB72, 0x737) facing 14; (0xAE1, 0x6FA) facing 14; (0xAE8, 0x772) facing 14;
(0xA61, 0x7F5) facing 12; (0xB00, 0x814) facing 12. Each call passes `pArea`
(the area is not otherwise used), a fresh `CPoint` built on the stack, and the
facing as the third argument.
