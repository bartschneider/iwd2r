## Notes

The original compares the upper-cased search string with each row label,
`m_pNamesY[y]` (`[[ecx+0x14] + y*4]`). On a match it sets ptLocation to (-1,
y) and returns TRUE. Otherwise it returns FALSE and leaves ptLocation alone.
Our port compared `m_pNamesY->Compare(...)`, which is always row 0. It found
row 0 at every y and nothing else.

Calling convention (objdump): `__thiscall`, `ret 8` at 0x403962, BOOLEAN in
al. It takes `(CString&, CPoint&)`.

Oracle case `tables/find_row` (oracle/cases/tables.cpp), on the fixtures of
403340.md. The words are every label and cell, each in upper and lower case,
the default, and the missing words, then 10,000 random ones per table with
each letter's case flipped at random. ptLocation starts as (-7, -7) on both
sides, and the case compares the result and ptLocation.

First run (20261012-225211, seed 1): FAILED, 40,192 inputs, 5,485 failures,
for example:

    table XPLEVEL.2DA: Find("BARD", CPoint(-7, -7))
      original 1, CPoint(-1, 1)
      ours     0, CPoint(-7, -7)

Fix: ours compares `m_pNamesY[y]`. The `#guess` mark stays, because it is
about the name. After the fix: run 20261012-225526 (seed 1, iterations 10000)
passed with 40,192 inputs and 0 failures, and so did run 20261012-225535 (seed
7).
