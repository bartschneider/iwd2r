## Notes

Ported from the disassembly. Our parameters are named for their use:
`bProgressBarRequired` (a1: open our own progress bar when none is in
place), `bProgressBarInPlace` (a2) and `bSaveScreen` (a3: sets
`field_366E`, which makes SynchronousUpdate write the save's screenshots).
Party Formation's Done calls SaveGame(0, 1, 0); CGameAIBase::FinalSave
SaveGame(1, 0, 1).

Not in the original: SaveGame first calls `iwd2r::ResetMarshalPtrs()`, so
each save is one pass of the pointer handles in compat/marshal_ptr.h.

Order: each area's 0x47A190 (music position); an empty `m_sSaveGame`
returns FALSE; the free-space check (GetDiskFreeSpaceA against
MINIMUM_DRIVE_SECTORS and MINIMUM_DRIVE_SPACE, then GetDiskFreeSpaceExA
through kernel32.dll stored in CResCache::pfnGetDiskFreeSpaceExA, 0x8E7514)
posts WM_CLOSE with strref 11790 and flags 0x34 and returns FALSE; the
progress bar (caption 9890, target 5000000) when required and not in place;
progress targets (2500000, 6000000 with a session, 3000000 per saved area);
the multiplayer host steps; `field_366E`; Icewind586B70::sub_587190; the
active screen and the caching screen invalidated; progress; every server
store's Marshal into `m_sTempDir`; CInfGame::Marshal and the write of
ICEWIND2.GAM through a CResHelper on ICEWIND2 (type 0x3F5) with
CRes::Write; every area whose header flag 1 is clear through
CGameArea::Marshal and a CResHelper on its resref (type 0x3F2); the TLK
override saved and closed; when everything succeeded, temp copied to
tempsave, then the save directory emptied and refilled from tempsave;
tempsave emptied; the override reopened on "temp//default.toh" and
"temp//default.tot"; the key table rescanned inside `field_314`;
SaveOptions on the game and on CBaldurChitin; `m_nLastSaveTime`; with a
session, the hard-pause wait (SynchronousUpdate each pass on the null
provider), returning TRUE if the session closed; the progress bar closed
when we opened it; and the second free-space check (strref 10249, flags
0x10, returns FALSE) or, when a step failed, WM_CLOSE with strref 23554 and
flags 0x34 (and TRUE).

The original's two session tests also require the multiplayer screen's
startup flag (CBaldurChitin + 0x1C90, +0x488) to be clear. ADR 0002 removed
that screen; in single player its flag is never set, so ours tests the
session only.

Partial (outside this stream's files), each a TODO in the code:
- 0x5170F0 on `m_cMoveList` and `m_cLimboList` (CMoveList);
- Icewind586B70's id list (0x587510) and CBaldurMessage 0x43D8D0 per id
  (a no-op without a network session);
- the world map write (0x558F40, CWorldMap);
- CDimm's packing of the area files into ICEWIND2.SAV (0x784A50). Without
  it the area files reach the save directory loose, and LoadGame's
  UncompressDirectory deletes them from temp, so a reload takes the areas
  from the game data instead of the save.

No oracle case: it needs a whole game and writes files. Run by Party
Formation's Done in `world_entry`.
