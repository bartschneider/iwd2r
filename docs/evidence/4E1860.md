# 0x4E1860 CUIControlEditMultiLineScroller::CUIControlEditMultiLineScroller

## Why ours was kept

The batch row flags WillScarlettOhara's fork (iwd2-re@e8dd16a750966af53f24daaf49dcb4fb13594c13,
read through git plumbing) as changed against our base body. Diffing his body
against ours shows the only differences are a single member rename: he reads ``controlInfo->m_nControlType`` where we read ``controlInfo->field_36``..

``m_nControlType`` does not exist in our UI_CONTROL structs; both
name the control-type field at +0x36 of the edit control's panel entry.

## The exe reading

Bundle decompile: ``uVar1 = *(ushort *)(param_2 + 0x36); ...
*(uint *)((int)in_ECX + 0x892) = (uint)uVar1;`` - the control-type halfword is
read from controlInfo+0x36 and stored to this+0x892, which is what our
``field_892 = field_36`` does.

Ours already matches the exe; adopting his naming would need header edits
outside this batch's owned files. Kept as ours.
