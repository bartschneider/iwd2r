# 0x54EF60 CTimerWorld::CheckForTriggerEventAbsolute

## Disassembly reading

- The exe gates the body on the active area (GetObjectArray slot at
  +0x37e0/+0x37e2, area flag +0x1ef) and dispatches on
  `time % 0x1a5e0`; ours checks the same through its `pActiveArea`
  lookups before any event fires.
- TIME_DAY (0x7b0c, 31500): `CGameArea::SetDay()` (0x477ee0), then the
  m_nLastPercentage byte at this+5 = 0xff. TIME_NIGHT (99000): SetNight
  (0x4781b0), then 0xff. Ours matches both.
- TIME_APPROACHING_DAWN (0x67b6, 26550) and TIME_APPROACHING_DUSK
  (0x16f62, 93538) both call the same 11-byte thunk
  CGameArea::SetApproachingDawn (0x478480), which jumps to the empty body at
  0x799ca0 - ours models this as the single SetApproachingDawn call from
  both of its branches.
- Dusk ramp: `-1 - ((time + 0xfe8edc) * 0x100) / 0x1194` with the
  CGameArea::SetDusk (0x478ac0) call only when the byte differs from
  this+5; dawn ramp the same around +0xff9688 with CGameArea::SetDawn
  (0x478490). Ours writes the same arithmetic in its TIME_DUSK..TIME_NIGHT
  and TIME_DAWN..TIME_DAY branches behind the same
  `nNewPercentage != m_nLastPercentage` guard.

## Notes

16682716 = 0xfe8edc, 16750216 = 0xff9688, TIMESCALE_MSEC_PER_HOUR 4500 =
0x1194. The fork's static_cast<BYTE> additions are no-ops on this
arithmetic; every other token it touches is a name declared outside the
owned files.
