## Notes

Ported from the Ghidra listing and the disassembly (0x5D00C0-0x5D07AF, `ret 0x14`): the scrolling
viewport's tile-request walk, called by `CInfinity::Render` (0x5CEFD0 at 0x5CF76C) when the scroll
state is neither 0 nor 9. It first cancels the previously remembered rect
(`CancelRequestRect(field_15E)`), then derives the flags byte for this pass:

- `field_158 & 0x40` selects `m_requestDayNightCode` (+0x15D) instead of 1;
- `field_158 & 0x04` with a nonzero `nCurrentRainLevel` (+0x128) sets bit 2;
- the byte is stored in `field_15E` and passed to every `RequestTile`.

The interior, one tile in from the requested edges (`x1+1 .. x2-2`, `y1+1 .. y2-2`, clamped to
`[0, nTilesX-1)`/`[0, nTilesY-1)` by `max(..., 0)` and `min(..., nTilesX/Y - 1)`), is requested at
priority 2 (`CDimm::PRIORITY_HIGH`). The `nScrollState` switch (jump table at 0x5D0790, cases 1-8;
`cmp edx, 7; ja default` at 0x5D01AB) then adds the one-tile border the scroll direction enters, at
priority 1 (`CDimm::PRIORITY_MEDIUM`):

- 1: the row above (`y1-1`), `x1 .. x2-1`;
- 2: the row above wider by one (`x1 .. x2`) and the right column (`x2`);
- 3: the right column;
- 4: the row below (`y2`) with the row above wider by one's x span, then the right column;
- 5: the row below, `x1 .. x2-1`;
- 6: the row below starting at `x1-1`, then the left column (`x1-1`);
- 7: the left column;
- 8: the row above starting at `x1-1`, then the left column.

The row/column clamps are the original's: starts are `max(..., 0)`, ends `min(..., nTilesX/Y - 1)`,
so a border entirely outside the map runs no requests. The decompile spells the clamp as
`((int)x < 0) - 1 & x` (0 for a negative, x otherwise). The default case asserts at
`C:\Projects\Icewind2\src\Baldur\Infinity.cpp:5161` (0x1429). After the switch the function
stores `field_196 = nScrollState` and `field_68/6C/70/74 = x1/y1/x2/y2` and returns 1. Nothing in
the function draws `rand()`.

The argument order is `(x1, y1, x2, y2, nScrollState)`; the decompile's `uint` parameters are the
same 32-bit values as the port's `int`s, so the clamps are unsigned-safe two's complement, as in
`RequestRect` (0x5CFE80). The loop bounds were checked case by case against the disassembly because
the decompiler aliases the `local_14`/`iVar3`/`iVar7` slots between the two loops each of cases 2,

## Oracle

`infinity/scrolling_request_rect` (oracle/cases/infinity.cpp) reuses the T85 WED fixture: a
synthetic 8x8 WED parsed by each side's own `CResWED::Parse` (0x401340), with each cell's
`WED_TILEDATA` naming its own tile as the *secondary* tile (`wFlags` 2, `nSecondary` = cell index)
and an identity tile list. RequestTile then reaches the tiles through `CRes::SetPriority/Request`
(0x77E670/0x77E610) and `g_pChitin->cDimm`, so the case provides the original's chitin at 0x8CF6D8
(a zeroed block whose `field_2FC` is initialized as a *native* kernel32 critical section - the
runner's `InitializeOriginalCriticalSection`, since the engine's own CRITICAL_SECTION is a
different, shimmed type) and ours as a zeroed `CChitin` with the shim's section.

Every input randomizes the rect (including outside the map), the scroll state (1-8), the day/night
and rain area bits, the day/night code, the rain level, the previous rect that the first
`CancelRequestRect` cancels (with `field_196` 0, so the so-far unported `ScrollingCancelRequestRect`
is not reached) and the tiles' pre-call request counts. It compares the WED image, `field_15E`,
`field_68/6C/70/74`, `field_196` and all 64 tiles' request count (`field_44`) and `dwFlags` (the
last priority). A visited cell gets two requests because RequestTile's secondary path requests
`nSecondary` in its first block and again in its last one; the counts still identify exactly which
cells the walk visited. The primary tile-list branch of the already-ported `RequestTile` is not
exercised (it is a different function; see report T86).
