# 0x5A9680 CInfGame::ProgressBarCallback

## Why ours was kept

The batch row flags WillScarlettOhara's fork (iwd2-re@e8dd16a750966af53f24daaf49dcb4fb13594c13,
read through git plumbing) as changed against our base body. Diffing his body
against ours shows the only differences are a single call-target rename: he tails with ``WaitForEngine(FALSE)`` where we call ``sub_59FA00(FALSE)``..

``WaitForEngine`` is his name for 0x59FA00 - the same function this
batch imports (its evidence file is docs/evidence/59FA00.md). Renaming the
callee here would ripple through CInfGame.h and every caller, outside this
batch's owned files.

## The exe reading

Bundle decompile tail: ``SleepEx(0x19,1); sub_59FA00(0);`` - the
Ghidra name for the call is literally the address 0x59FA00, which is what our
body calls.

Ours already matches the exe; adopting his naming would need header edits
outside this batch's owned files. Kept as ours.
