## Notes

Filed by hand for the creature ability order in src/FileFormat.h (commit
d30a671). That change renamed CCreatureFileHeader's fields, so
`tools/check_evidence.py`, which ignores headers, did not ask for it; this is
the function that reads the layout.

Calling convention (objdump): `__thiscall` with the CDerivedStats in ecx,
moved to ebp at 0x444114. The creature header is the second stack argument
(`mov ebx,[esp+0x8C4]` at 0x44410C, after the 0x8AC frame, the three SEH
pushes, the return address and the saved ebx: the first argument is the
sprite).

The base abilities, objdump 0x444409-0x44444D: each is a header byte
zero-extended into a derived-stats SHORT (`movzx r16,byte [ebx+H]; mov
[ebp+D],r16`):

| Header | Derived | Ability |
|---|---|---|
| +0x25E | +0x54 | STR (m_STRBase to m_nSTR) |
| +0x25F | +0x56 | INT |
| +0x260 | +0x58 | WIS |
| +0x261 | +0x5A | DEX |
| +0x262 | +0x5C | CON |
| +0x263 | +0x5E | CHR |

The byte before them, +0x25D (sex), goes to +0x52 at 0x4443FD. Ghidra shows
the same reads (`param_2 + 0x25e` to `in_ECX + 0x15`, an index into an
`int *`, so +0x54, and so on). CDerivedStats.h names +0x54..+0x5E m_nSTR,
m_nINT, m_nWIS, m_nDEX, m_nCON and m_nCHR, so the header holds STR, INT,
