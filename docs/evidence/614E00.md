## Notes

Ours compared the export list's names with `==`, which is case-sensitive.
The original compares with the CRT's _mbsicmp (`call 0x7E8182` at
0x614E76, the case-insensitive multibyte compare), so "Probe" matches the
"PROBE" that CInfGame::GetImportCharacters (0x5C3240) upper-cases into the
list. Ours now uses CString::CompareNoCase, as the other case-insensitive
compares in our tree (CDimm) do. Without it a second export of a character
named Probe overwrote PROBE.CHR instead of going to PROBE00.CHR. One difference
remains: _mbsicmp folds case by the CRT's multibyte code page (Latin-1
letters on code page 1252, and it skips DBCS trail bytes), while
CompareNoCase folds ASCII only, so the two differ for export names with
non-ASCII letters only.

No oracle case: it needs the export list built from the Characters folder.
Pinned by tests/test_gam.cpp ("gam: character export overwrites a junk
PROBE.CHR and numbers past a valid one").
