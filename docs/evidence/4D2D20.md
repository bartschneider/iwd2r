# 0x4D2D20 CUIPanel::sub_4D2D20

## Why ours was kept

The batch row flags WillScarlettOhara's fork (iwd2-re@e8dd16a750966af53f24daaf49dcb4fb13594c13,
read through git plumbing) as changed against our base body. Diffing his body
against ours shows the only differences are his function name (``CUIPanel::Hide``) and one member rename: he writes ``m_bHidden`` where we write ``field_112``..

``m_bHidden`` does not exist in our ``CUIPanel.h`` (our ``m_bHidden``
hit is ``CUIManager.h``, a different class). Both name the panel's hidden
marker at +0x112; his Hide/Show naming also cannot be adopted without touching
every caller, outside this batch's owned files.

## The exe reading

{ *(ushort *)(in_ECX + 0x3c) &= 0xfffe; *(undefined4 *)(in_ECX + 0x112) = 1;
return 1; } return 0;`` - flags at +0x3C, marker at +0x112. Our body reads and
writes the same two offsets with the same truth table.

Ours already matches the exe; adopting his naming would need header edits
outside this batch's owned files. Kept as ours.
