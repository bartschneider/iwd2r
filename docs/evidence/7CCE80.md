## Notes

Ported from the Ghidra listing and the disassembly (0x7CCE80-0x7CD5D4, `ret 0x18`): a 24-bit BMP
(three bytes, B then G then R; `nDataJump` bytes skipped after each row) onto a 24-bit surface, the
same source and row geometry as `BltBmp24To24` (0x7CCBF0). The channel shifts are the mode's
`m_dwRBitShift`/`m_dwGBitShift`/`m_dwBBitShift` (0xAA/0xAE/0xB2, `CVidInf::ParsePixelFormat`), so
the function follows the surface's layout - the oracle case runs shifts 16/8/0 and 0/8/16. `lPitch`
is in bytes and the rows go bottom-up (`pSurface -= lPitch`). The tint, add and light passes are
`CVidImage::GetTint`/`GetAdd`/`GetLight` against the bitmap's `m_paletteAffects` (the original at
+0x28, ours at +0x30 on 64-bit - the oracle case fills each at its own offset), exactly as the
32-bit sibling `BltBmp24To32Tint` (0x7CD870) uses them.

Two forms, selected by bit 0 of `dwFlags`:

- unkeyed: grey (0x80000, `r = g = b = (r + g + b) >> 2`), then tint, add and light per channel.
  This is the sibling's plain branch, including its whole-register quirks: the add step inverts only
  the low byte of a 32-bit value, and the light step (`* light >> 3`) clamps only the low byte to
  0xFF, keeping the higher bits that then carry into other channels of the 24-bit write.
- keyed (0x1): pure green (`0, 255, 0`) is transparent (the destination keeps its pixel); with 0x4 a
  pure black pixel is a shadow - half of the destination plus the mode's brightness/contrast black
  (`ApplyBrightnessContrast(0)`); every other pixel takes the grey/tint/add/light passes, truncated
  to bytes, and the light keeps the result off the transparent colour (`g = 254` when it lands on
  pure green). A black pixel without 0x4 is written as black.

Two read/write quirks the bytes decide:

- a drawn pixel other than a row's last writes **four** bytes, the fourth landing on the next
  pixel's first (which a skipped pixel keeps); the row's last pixel writes three, so the row ends
  at its third byte.
- the row's last pixel's shadow reads a **WORD** for red and green (through their shifts) and the
  third byte for blue, while the other pixels read a DWORD. With shifts 16/8/0 the last pixel's red
  therefore stays at the black level and its blue halves the destination's red byte.

The original's unkeyed loop walks `width - 1` pixels with a do-while, so a width below two never
ends, and runs its rows body first, so a height of 0 still draws one row. The keyed loop guards both
(a width below two draws only the row's last pixel - one pixel per row at width 0) and tests the
height first. The port uses the per-pixel loops, exact for every width of two and up; `RenderDirect`
passes wider bitmaps and the oracle case sweeps widths 2..32 (both parities).
