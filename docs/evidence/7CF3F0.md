## Notes

The 24-bit clear-shadow blit of `CVidCell::Render`'s `0x4` +
`TRANSLUCENT_SHADOWS_ON` branch (report-T50.md section 2 group A/B; the
dispatchers are 0x7AE5D0 and 0x7AEAD0). It is the direct sibling of
`sub_7CECD0`/0x7CECD0: the same 24-bpp palette realization (`Realize`,
24 bpp, fixed 255), the same frame data and transparent index, the pitch
kept in bytes (`lPitch - width * 3` once, added after each row), three
bytes written per pixel (the low word of `rgbTempPal[i]`, then its third
byte), and the same compressed run walk with the same row-jumping run
accounting.

The difference is the shadow entry:

- with `m_bShadowOn` (the byte at +0xD4) set, a source pixel whose index is 1
  (`SHADOW_ENTRY`, the literal `cmp eax,1` at 0x7CF5A8 and 0x7CF609) draws
  the destination pixel halved: the three destination bytes are assembled
  into a dword (`B` in bits 0..7, `G` in 8..15, `R` in 16..23, the
  `mov dx, word [edi+1]; shl edx,8; mov dl, [edi]` at 0x7CF5AD-0x7CF5B4),
  shifted right once and masked with the mode's shadow mask, stored back as
  three bytes. The mask is computed once at 0x7CF4B1-0x7CF4D0 as
  `(RBitMask >> 1 & RBitMask) + (GBitMask >> 1 & GBitMask) +
  (BBitMask >> 1 & BBitMask)` - for the 24-bit masks 0x00FF0000/0x0000FF00/
  0x000000FF that is 0x007F7F7F, each channel halved with its low bit
  trimmed;
- with the shadow off, `rgbTempPal[SHADOW_ENTRY]` is written from the mode's
  `field_24` (0x7CF487-0x7CF492, the same as the sibling) and index 1 then
  draws from the realized palette like any other.

Two details kept as the exe does them:

- the zero-sized frame answers TRUE before any palette work, i.e. the
  width/height tests at 0x7CF40C/0x7CF41A come first (the 32-bit twin
  returns FALSE for the same frame);
- the **raw** (uncompressed) path skips palette index 0, not the frame's
  transparent index: at 0x7CF61D the original does `and eax,0xff; je` and
  never compares against the header's `nTransparentColor` (the compressed
  path does compare, at 0x7CF55B). An uncompressed frame whose transparent
  index is not 0 therefore draws its transparent pixels from the palette and
  leaves index 0 alone; the case mixes both.

`kind: oracle`: the case runs in the gate on our Windows rig (the run below).
`tests/test_vid.cpp` ("blt8to24_clear_shadow") pins the two shadow branches,
the raw path's index-0 skip and the zero-size return in the harness's own
terms; against the stub 9 of its 16 assertions fail.
