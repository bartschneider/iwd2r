## Notes

Checked against the disassembly (0x5525C0-0x5526DF). The four visibility
tests (`test BYTE PTR [map+n], 0x3f`, a tile off the map counting as unseen)
set bits 0x1 (the tile), 0x2 (below), 0x4 (below right) and 0x8 (right);
then `shl bl, 4` (0x552668) moves them to the high nibble, and the four
explored tests (`shr al, 7`, bit 0x80) set the same bits in the low nibble.

Fixed: ours shifted by 8 (`code <<= 8` on a BYTE), which left the high
nibble 0, so BltFogOWar's dither pass (and BltFogOWar3d's visibility pass)
never saw an unseen corner. The rest matched.

No oracle case: a case would need a CVisibilityMap in the original's heap;
the function only reads m_pMap, m_nWidth, m_nHeight and m_nMapSize, and the
unit test pins the bit layout on a 4x2 map, including the tile off the map
and the right neighbour that wraps to the next row.
