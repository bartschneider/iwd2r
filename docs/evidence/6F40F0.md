## Notes

Ported earlier; this entry records one fix. A party member entering an area counts in the area's BYTE m_nCharacters: the original tests `cmp al, 0xff` (0x6F4511) and stores 1 when the count is 0xFF (set by the area load), else increments it. Ours compared the BYTE with the int -1, which never matches, so the 0xFF wrapped to 0 and the area counted no characters; CGameSprite::AIUpdate's paused branch then never ran CheckIfVisible (m_lastCharacterCount != m_nCharacters), Hedron was never seen, and CGameSprite::DoAIUpdate's inhibitor held him back one paused update too many (frame 1497 of walk_and_talk). Replay-verified with IWD2R_RAND_TRACE (docs/rand-trace.md) on walk_and_talk, seed 1: with the round-2 fixes our AI thread's rand() calls in the load frame (Party Formation's Done, frame 1491) and the paused frames after it (1492-1497) match the original's call for call.
