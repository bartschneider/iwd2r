## Notes

The edge of the clicked point (TRAVEL_WIDTH search squares: west, east,
north, south, else west) gives LeaveArea (91) with the edge's area name, the
point and the direction (0, 4, 8, 12) with the edge flag's bit 0 in bit 16;
m_lastClick is reset (m_lastTarget INVALID_INDEX, 0x851878). The group gets
the LeaveArea with its actions cleared (push 1), then MoveToPoint (23,
0x8477B0) to the point, specificID 0, specificID2 -1, without clearing
(0x475C69: push 0, push 0, the copy of the action built at esp+0xF8).

Fixed in round 4 of the ui-misc stream (ruling M5-17): ours built the move
and gave the group the LeaveArea a second time with its actions cleared,
so the party never walked to the edge. AddAction puts each action at the
head and GetNextAction takes the head, so the walk runs first and one
LeaveArea follows it. Checked by tests/test_ui_misc.cpp "travel: a click at
the area's edge queues the walk before one LeaveArea".
