# 0x786180 CDimm::FindFileInDirectoryList

## Disassembly reading

- The walk: `esi = [esi+0x27C]` takes the m_lDirectories list head;
  each node's CString is copied into a local through operator= 0x7FCD07
  (`lea ecx,[esi+8]`).
- The searched path: CString Concat 0x7FCDFD with sret destination,
  pushed sDirName (ebp) first and the element second, so the built path
  is `element + sDirName` - the directory entry first, the requested
  file name second.
- The hit path: FindFile 0x7E67E7 returning nonzero jumps to the tail
  that assigns the element into sFileName (the sret argument) and
  returns 1; the miss path falls through the local CString destructors
  and returns 0.

## Notes

Ours built the path as `sDirName + v1` - the operands reversed - so the
name was prepended to the directory entry instead of appended. The
import is that one operand order; the rest of the body (list walk,
sFileName assignment on a hit, both returns) already matched the exe.
The fork body uses the exe's operand order and is otherwise ours modulo
the member renames declared in headers this batch does not own.
