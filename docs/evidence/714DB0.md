# 0x714DB0 CGameSprite::InitQuickItemData

## Disassembly reading

- The exe, inside the ability branch: copies the ability's quick slot
  icon into the button, copies the item's generic name, then `mov word
  ptr [param_4+0x1A], 2` (bundle: `*(undefined2 *)(puVar3 + 0x1a) =
  2`), then item number, ability number, target type, description string
  id with the -1 fallback to GetGenericName, count handling and the
  launcher pair.
- param_4 is the CButtonData out-parameter; m_abilityId sits at
  CButtonData+0x1A and m_itemType is its first member (CAbilityId layout
  verified against the 0x504630 ctor), so the exe's +0x1A word store is
  `m_abilityId.m_itemType = 2`.
- Ours set every field except m_itemType, leaving whatever value the
  button data carried in; the fork body adds exactly that one store.
