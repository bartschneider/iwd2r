## Notes

Filed by hand for the replay dump's `world` block (oracle/replay/schema.json,
x-fields): `tools/gen_fields.py` takes these offsets from the `/* NNNN */`
comments of our headers, which `tools/check_evidence.py` does not check, and
the recorder reads them from the original's memory. This is a function that
reads the layout; the comments were already right, no header changed.

Case 1 (the maximum hit points stat) returns `(short)*(this + 4)`:
CDerivedStatsTemplate::m_nMaxHitPoints, as in 0x706720. Case 0x19 and cases
0x1A-0x1D, 0x21, 0x5A, 0x5E read single `char`s at `this + 0x144..0x153`, the
skill bytes CDerivedStatsTemplate::m_nSkills[64] at 0x144 (ours copies 64
bytes there from the creature's m_skills in CDerivedStats::Reload). Field
`sprite_skills` (u8 x 64, 0x0920 + 0x144 = 0x0A64).

The original reads these bytes as signed chars; our header declares them
BYTE, so the dump writes them unsigned (a skill of -1 shows as 255) on both
sides. Changing the header's type would change the engine, which the
creature-file stream owns.
