## Notes

Ported (Task 6). Calling convention (objdump): `__thiscall`, five stack
arguments, `ret 0x14` (0x70BECE).

Layout read from the decompile and the disassembly:

- The Constitution bonus m_nHPCONBonusTotalOld (0x7234, read as a 16-bit
  value) is taken off m_baseStats.m_hitPoints (0x5C0),
  m_baseStats.m_maxHitPointsBase (0x5C2) and m_derivedStats.m_nMaxHitPoints
  (0x924) before the header is copied and added back at the end
  (0x70BE76-0x70BE8B), so the file holds hit points without it.
- m_baseStats.m_effectVersion (0x5CF) is set to 1; the effects are always
  written as CGameEffectBase (0x108 bytes, `CGameEffectList::Marshal(&p, 1,
  a4 == FALSE)`).
- `*facing` is m_nDirection (0x5380).
- The size: 16 bytes per spell plus 8 per list for the 7x9 class lists
  (m_spells, 0x4284, 0x100 per class, 0x1C per level), the 9 domain lists
  (m_domainSpells, 0x4984), innates (0x4A84), songs (0x4AA0) and shapes
  (0x4ABC); then the equipment block (0x68) and 0x14 per item from
  CGameSpriteEquipment::Marshal (0x7124C0, with a5); then the effects; then
  0x62E (900 for the signature and the 0x37C header, 0x2AA for the offsets
  block).
- With a4 set, `m_pLocalVariables->MarshalToCharacter(this)` (0x70B50A:
  `mov ecx,[ebp+0x72B2]; mov eax,[ecx]; push ebp; call [eax+0x10]`, vtable
  slot 4 of CVariableHashBase). Without it the original stores 0xFFFF at
  0x70B539 (`mov WORD PTR [esp+0xa6],0xffff`, two pushes after the frame
  base, so frame offset 0x9E): the equipment block lives at `[esp+0x3c]`
  (pushed to 0x7124C0 at 0x70B4DB), and 0x9E - 0x3C = 0x62 is
  m_miscItem[27], the magic weapon slot. The block is copied into the file
  (0x70BDA1), so without a4 the magic weapon slot is written as empty.
  Ghidra's "Removing unreachable block" dropped the store; ours keeps it
  (fix round 1; an earlier version of this note called it a dead store).
- m_baseStats.field_2F8 (0x89C) takes the low byte of m_removeFromArea
  (0x5644); m_baseStats.m_subrace (0x7FF) takes m_startTypeAI.m_nSubRace
  (0x3E3D).
- The offsets block at +900 is filled from m_startTypeAI (0x3E36): enemy-ally
  +4, race +6, class +8, instance +0xA, special case +0xE (5 bytes), specific
  +0x13, gender +0x14, alignment +0x15, avclass +0x16, class mask +0x18; the
  general comes from m_liveTypeAI (0x3DFF, +5 of 0x3DFA). The name is
  m_scriptName (0x554), the dialog m_dialog.
- Items and effects get an offset and count only when there are any; their
  buffers are freed (operator_delete; ours `delete[]` on the types they were
  allocated as).
- Last, `RemoveAllOfType(this, 0xBA, list.m_posCurrent, -1)` on
  m_equipedEffectList (0x54FA, +0x20) and m_timedEffectList (0x5526, +0x20),
  0x70BE92-0x70BEBF. 0xBA is CGAMEEFFECT_JUMPTOAREA.

Our CCreatureFileHeader (src/FileFormat.h) is 0x2AC bytes, the original's
0x37C (the 0xDF-dword copy at 0x70B5FC, the same in Unmarshal at 0x70D1D2, and m_baseStats at 0x5A4 up to
m_derivedStats at 0x920): the members after field_294 are declared at the
original's offsets but packed without the gaps. `sizeof(m_baseStats)` here
and in Unmarshal copies what ours has; the header's last 0xD0 bytes are
written as zeros until the layout is fixed (reported to the coordinator;
FileFormat.h is not this stream's file). CHARBASE.CRE has zeros there.

No oracle case: the function reads the whole sprite (spell lists, equipment
with loaded CItems, effect lists, the local variables). Covered by
tests/test_cre.cpp (`[cre][data]`): CHARBASE.CRE unmarshalled and
marshalled gives the original header (apart from the documented changes),
and a second Unmarshal/Marshal gives the same bytes.
