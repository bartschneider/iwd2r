# 0x533600 CProjectileSPBRNHND::SpawnSpray

## Decompiled (Ghidra, driver bundle 0x533600)

Recursive seeder for the SPBRNHND ("spray" projectile) impact burst: from the
impact point it projects one step along the eight signed-WORD direction
tables at 0x84d6b8..0x84d798 (indexed by the facing word), news a spray cell
there with the parent's animation resref, lifetime, palette and has-height
byte, moves it into the area, and — unless `oneSide` — news a mirror cell on
the opposite side of the line of flight; then it recurses from each spawned
point with `count - 1` while that is still positive.

The bundle rendering carries three artifacts that the raw exe bytes
overrule (all noted in the exemption):

- The SEH try-level slot is folded into the locals, so the recursion guard
  reads as `if ((short)local_4 != 1 && -1 < (short)local_4 + -1)` and the
  right-recursion appears gated on `piVar3 == 0`. In the exe the guard
  is `(SHORT)count - 1 > 0` (movsx/dec at 0x5338b8) and both oneSide gates
  are `cmp DWORD [esp+0x3c], ebx` with ebx zeroed (0x5337d9, 0x5338d7).
- The `mov DWORD [esp+0x34], 0xffffffff` before each virtual call looks
  like a clobber of the count argument; with three argument pushes live it
  lands 0xc higher, on the SEH try-level slot S+0x28 (the classic MSVC
  state write before a throwing call). Count at S+0x34 is read intact at
  0x5338b8.
- The bundle's callgraph shows "(no callers)"; the .text scan finds
  0x5331de inside SPBRNHND::Fire 0x532f00 plus the two recursive sites.

```cpp
void CProjectileSPBRNHND::SpawnSpray(const CPoint& origin, LONG count, SHORT facing, BOOL oneSide)
{
    CPoint left(SprayAdd(origin.x, static_cast<SHORT>(SprayProjection(14, SPRAY_VECTORS[0][facing], 32, SPRAY_VECTORS[1][facing], 1))),
        SprayAdd(origin.y, static_cast<SHORT>(SprayProjection(14, SPRAY_VECTORS[2][facing], 32, SPRAY_VECTORS[3][facing], 1))));
    CPoint right(SprayAdd(origin.x, static_cast<SHORT>(SprayProjection(14, SPRAY_VECTORS[4][facing], 32, SPRAY_VECTORS[5][facing], 1))),
        SprayAdd(origin.y, static_cast<SHORT>(SprayProjection(14, SPRAY_VECTORS[6][facing], 32, SPRAY_VECTORS[7][facing], 1))));
    auto* first = new CProjectileSprayCell(m_animation->cResRef, m_animationLifetime, facing, m_palette);
    first->m_bHasHeight = m_bHasHeight;
    first->AddVisualToArea(m_pArea, left, m_posZ);
    if (!oneSide) {
        auto* second = new CProjectileSprayCell(m_animation->cResRef, m_animationLifetime, facing, m_palette);
        second->m_bHasHeight = m_bHasHeight;
        second->AddVisualToArea(m_pArea, right, m_posZ);
    }
    if (static_cast<SHORT>(count) - 1 > 0) {
        LONG next = SprayAdd(count, -1);
        SpawnSpray(left, next, facing, TRUE);
        if (!oneSide) {
            SpawnSpray(right, next, facing, FALSE);
        }
    }
}
```

The eight direction tables are byte-exact from .rdata (mechanically
compared) and the arithmetic helpers carry the exe's wrap/truncation
behavior; both live in an anonymous namespace directly above the function in
`src/CProjectile.cpp`:

- `SPRAY_VECTORS[8][16]` — rows at 0x84D6B8 + 0x20*n, one row per component
  slot in the exe's load order.
- `SprayAdd(a, b)` — the additions wrap as DWORD in the exe.
- `SprayProjection(a, av, b, bv, count)` — `a*av + b*bv` as DWORD sums,
  times `count`, then the signed /1000 (the exe's `0x10624dd3` magic
  sequence); the caller truncates with `static_cast<SHORT>`, matching the
  exe's `movsx`.

The class is declared in `src/CProjectileBAM.h`, anchored on the
CProjectileBAM constructor 0x52AD60 that the SPBRNHND constructor 0x532CA0
chains to; `m_animationLifetime` is the +0x2A0 word of that family.

## Fork comparison (rule 1)

WillScarlettOhara's body (@e8dd16a7, `CProjectile.cpp`) is ported verbatim
apart from tree formatting: same projection expressions, same guard order
(second cell → recurse left → recurse right under `!oneSide`), same
recursion arguments, and his `SPRAY_VECTORS` rows equal the exe tables
1:1 (mechanically byte-compared this session — all 128 shorts). Differences:

- His spray-cell constructor is an inline in his `CProjectile.h` (class
  marked `/*#guess*/`) that also stores tinted/mirror/direction-count fields
  the exe's inline ctor never touches (0x533729/0x533806 write only the
  zeroes, the lifetime, the 0x10 word and the facing). The exe is the
  verdict, so the ported constructor omits those stores.
- The bundle's SEH-slot artifacts (guard renderings, missing callers) are
  bundle quirks, not fork errors; his guards match the raw exe bytes.

## Notes

The count argument is a cell-per-32-pixels ray length: Fire passes the
flight distance divided down, and each recursion decrements it as a signed
WORD (`movsx` before the `dec`), which is why the guard tests `(SHORT)count
- 1 > 0` rather than the LONG. The `left`/`right` naming follows the exe's
use of the tables: rows 0-3 step one way from the impact point and rows 4-7
step the mirrored way, and the `oneSide` flag suppresses the mirror while
recurring down the left ray so each generation contributes one cell per
side, not a tree.
