## Notes

Not ported here: this change fixes deviations of the existing port from the original, found against the decompile and the disassembly (0x5492E0-0x54A1C4):

- The request loop runs while either list has a request (`count != 0` on the front list at 0x5493B2, or on the back list at 0x5493BC); the port required both, so no request was ever serviced unless both lists held one.
- A request whose source cannot be had (or is off the search map or in another area) is set to STATE_ERROR and left to its sprite (CGameSprite::AIUpdateWalk deletes it); only a stale one is deleted here (0x54A10A-0x54A132). The port deleted it in both cases, leaving the sprite a freed request.
- A target object that is not a sprite still counts as a target (the flag at esp+0x3C is set in both branches, 0x5497BB and 0x5497F5), with no personal space.
- The targets are taken off the snapshot at their own squares (goalRemoveObject, the array at esp+0x130 filled at 0x5497A5 and read at 0x549CDA), not at the goal points.
- The goal points are divided into search squares (x / 16, y / 12) just before SnapshotAdjustTarget (the idivs at 0x549E6F and 0x549E7E); the request holds them in pixels.
- A search from the back list (LIST_BACK_PROMOTE) starts at the request's m_sourcePt, where the previous partial path ended (`lea edx, [ebp+0x30]` at 0x549FFC), and uses m_minNodesBack/m_maxNodesBack; the front list starts at the source's square.
- The grid rectangle's left and top are 0 (set at the start, 0x54930A-0x549316).
- A target or party member refused by the object array is retried 256 times (the counter is tested before it wraps).

Unchanged and as the original: the lock is held from the last request's DONE state to the next request's PROCESSING state; targetIdPresent is set once and never cleared for the thread's life, so after the first request with a target object every later one counts as having a target (reproduced).

Exemption: the search thread needs the game's request lists, the object array, the path search and its semaphore; covered by the walk_and_talk replay's `moved` checkpoint, whose path comes from here.
