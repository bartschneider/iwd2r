## Notes

Ported from the Ghidra listing and the disassembly (0x54E5B0-0x54E82F, `ret 0x4`): the tiled
object's tile-state update, called by `CGameArea::Render` (0x477740) once per frame. The class keeps
two words, the *requested* state (`m_wAIState`, this+0x8) and the *applied* one (`m_wRenderState`,
this+0xA); the function copies the first into the second and, when they differ and
`m_nWedIndex != -1`, updates the object's tiles and polys to the new state:

- the object's tiles are the entries `nStartingTile .. nStartingTile + nNumTiles - 1` of the WED
  object tile list (`CResWED::GetTiledObjectList`, 0x4012C0); each names a `WED_TILEDATA` through
  `GetTileData(0, nTile)` (0x401220), whose `wFlags` (+0x8) takes the new state and whose VRAM image
  is swapped through `CInfinity::SwapVRamTiles` (0x5D2350): in the primary state detach
  `tileList[nStartingTile]` and attach `nSecondary`, in the secondary state the reverse
  (`CResWED::GetTileList(0)`, 0x4012E0, maps the tile's first image number);
- the tiled object's poly lists (`WED_TILEDOBJECT`, +0xA/+0xC/+0xE/+0x10/+0x12/+0x16): the primary
  polys clear `WED_POLYLIST.nType`'s bit 1 in the primary state and set it in the secondary one, the
  secondary polys the reverse. The count is skipped when it is -1 (0xFFFF) or 0, and the address is
  `m_pResWed->m_pHeader + nOffsetToPrimary/SecondaryPolys + i * sizeof(WED_POLYLIST) + 8` - the
  offsets are byte offsets into the WED data (0x54E6DC/0x54E7B6).

The swap's argument order is easy to misread in both call sites because the *first* argument is the
*last* push: the primary branch (0x54E790-0x54E79A) pushes `nSecondary` and then
`tileList[nStartingTile]`, so it detaches `nSecondary` and attaches the primary; the secondary
branch (0x54E6B4-0x54E6BC) is the reverse. The `nNumTiles` loop's end is the 16-bit
`nStartingTile + nNumTiles`, so a wrapped sum runs no tiles. (The Ghidra listing has this order
right; an earlier reading of the push order in this port had it backwards and the oracle caught it.)

The asserts are the original's: `m_pResWed != NULL` (line 84), `GetTiledObjectList() != NULL` (99)
and the state being 1 or 2 (130). Nothing in the function draws `rand()`.
