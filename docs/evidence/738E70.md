## Notes

New port (`CGameSprite::AttackReevaluate`, the AttackReevaluate action 134;
the sprite ExecuteAction's case at 0x72A33E calls it). At the action's first
update the actee is decoded into m_acteeID2 (+0x4F0); the target is shared
from it. Like Attack it checks the target and weapon (here an ability-less
weapon is UNUSABLE too, and an empty weapon slot returns ERROR without the
auto-pause), shows "Attacks" once per target, the battle cry (without
Attack's test of the action id), the battle music, and swings when in reach
and sight or walks to the target. After the action's specific value of
updates (m_curAction.m_specificID < m_actionCount) it is DONE, so the script
chooses again. An invalid target (gone, in flight, unseen, in sanctuary,
itself, dead, asleep against a non-monk's fist) is replaced by the nearest
creature of the actee's type (GetNearest with the visible terrain table,
line of sight, ignoring the sleeping), which becomes m_acteeID2.

NOTE: After a swing with the frame at 0 the original returns DONE without
releasing the target's share when the action is 105 (0x739A80); this cannot
happen while the action is AttackReevaluate, and ours does the same.
