## Notes / original defects

- The exe has no null branch between `operator_new` and the first `SetResRef`:
  on allocation failure it would call through NULL (MSVC6 `operator new`
  returns NULL). The port stops after releasing the CRE data and records the
  deviation here (crash avoided; no observable behaviour otherwise).
- The static "corcat" CString is registered with `atexit` in the exe; the
  function-local `static CString` gives the same one-time construction and
  exit destruction without the manual guard.
- The exe re-sets the resref twice (first from the CRE handle's cached resref,
  then from the literal); the port keeps both stores.
- Unexecuted: the whole body — no deterministic fixture provides the area,
  the "corcat" CRE and the object array. Verified: the listing/decompile
  control flow, the API mapping above, and the caller's SP reachability
  (5818F0.md).
