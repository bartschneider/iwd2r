## Notes

Ported from the decompile; was a stub returning FALSE. Unreachable in iwd2r: the DirectDraw shim lists only 32-bit modes, so CVideo never selects 24 bpp; ported for the record. The colour table realized at 24 bits with 0x800000 (as BltBmp8To32 does at 32), then each pixel written as its entry's DWORD at three-byte steps (the fourth byte landing on the next pixel's first, overwritten by it) and a row's last pixel as a WORD and a BYTE; the data moves past the row and the jump, the destination up a row (the bitmap is bottom-up). NOTE: the original's do-while over width - 1 pixels never ends for a width of 1; ours draws it; RenderDirect passes wider bitmaps. No oracle case: the original reads its CResBitmap, which no honest fixture builds; tests/test_vid.cpp blt_bmp8to24_and_24to24 checks a two-row bitmap by hand.
