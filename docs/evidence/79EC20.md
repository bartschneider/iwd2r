## Notes

Ported (was inherited from CVidMode's stub, which returned FALSE, so a save had no ICEWIND2.BMP screenshot and no PORTRTn.BMP portraits). Ghidra names it CVidMode_VFTable_110: it is CVidInf's vtable (0x85DF88) slot +0x110, PrintSurfaceToBmp, called by CInfGame::SynchronousUpdate (0x5BE900: surface 0 at scale 5 for the screenshot, surface 2 at scale 2 per portrait) and CVidInf::PrintScreen (scale 1). It allocates (w + pad + 2w) * h + 0x36 bytes with w, h the rectangle's size divided by the scale (pad = 4 - (-w & 3) when that is not 0), writes a BITMAPFILEHEADER and a 40-byte BITMAPINFOHEADER (24 bits; NOTE: biClrUsed 0x1000000 as the original writes it), locks the surface on the rectangle, and fills the rows bottom up: each output pixel is the average of a scale-square block (the last column takes the remaining width, the height is truncated), B, G, R. At 16 bits the channels are masked (m_dwBBitMask +0x20, G +0x1C, R +0x18), shifted down (+0xB2, +0xAE, +0xAA) and the average scaled `<< 8 >> count` (+0xBE, +0xBA, +0xB6); at 24 and 32 bits each channel is the byte at its shift / 8. It unlocks through the surface's Unlock. A failed lock or another depth frees the buffer, clears it and returns FALSE. NOTE: the original's first branch, when cVideo is 3d accelerated (+0x91C), calls the 3d variant 0x7BE5A0, which reads the OpenGL frame buffer; iwd2r refuses the 3d mode (spec 4.3), so ours returns FALSE there. The padding bytes are left uninitialized as in the original. The running engine's surfaces are the DirectDraw shim's XRGB8888 (32 bits); with the render API's backend installed (src/render/api.h) the surfaces would not hold the drawing, which concerns that project, not this function.
