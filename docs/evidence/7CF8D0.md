## Notes

Ported from the Ghidra listing and the disassembly (0x7CF8D0-0x7CFBB1, `ret 0x10`; was a stub
answering TRUE): the `CVIDIMG_TRANSLUCENT` branch of the 24-bpp dispatch (report-T50.md group A/B;
survey name `Blt8To24Translucent`, the export has only the address, so the code keeps the `sub_`
name as `sub_7CECD0` does). The frame size comes from the cell's `m_pFrame` (+0xD0, the WORDs at
+0/+2), the palette is realized for 24 bpp with a fixed 255 into the **global** realized palette
(`CVidImage::rgbTempPal`, 0x9064F8; `Realize(&rgbTempPal, 0x18, dwFlags, this+0x2C, 0xFF)` at
0x7CF9B3) after the `m_bPaletteChanged`-gated `SetPalette`, and `!m_bShadowOn` overwrites the
shadow entry (index 1, the byte at 0x85E854) with the mode's `field_24` (0x7CF9C9). Unreachable in
iwd2r, which runs at 32 bpp only (the DirectDraw shim lists no 24-bit mode); ported for the record.

The walk is the fast 24-bit blit's (0x7CECD0): the transparent index from the BAM header (+0xB) is
the RLE command byte, a run is its following byte + 1 and may span rows (the original's hand-written
assembly unrolls the row ends at 0x7CFA37-0x7CFA68; the port keeps the state-machine form the
sibling's oracle already proves), the raw walk is a plain per-pixel loop; both advance three bytes
a pixel and `lPitch - width * 3` after each row (bytes, rows bottom-up). The blend is per byte,
`dst = (src * (256 - nTransVal) + dst * nTransVal) >> 8` (`imul`/`add` then the `dh` byte store in
the compressed branch, `sar 8` and the `dl` store in the raw one — the same value), red to byte 2,
green to byte 1, blue to byte 0; `UTIL_ASSERT(nTransVal <= 256)` (ChVidImage24.cpp:4516).

Two differences from the 32-bpp `sub_7D0950`, both the original's and both kept:

- a drawn pixel whose realized colour equals the mode's shadow colour is **skipped** (the compare
  at 0x7CFA79 jumps past the write at 0x7CFA7C); the 32-bpp form draws it opaque.
- the raw walk's skip tests the palette entry's **first (blue) byte** against the whole shadow
  colour (`cmp edx, ebx` at 0x7CFB28 — a full-width compare, so a shadow colour above 255 never
  matches) and against the transparent index (`cmp cl, [ebp+0xF]` at 0x7CFB2C): the hand-written
  code clobbers the colour register with that byte at 0x7CFB19 before comparing. The 32-bpp form
  tests the index itself. With the usual shadow colour 0 a raw frame drops every pixel whose blue
  channel is 0.
