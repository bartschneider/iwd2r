## Notes

Ported (src/CRuleTables.cpp). Oracle case rules/starting_hp compares the
original with ours over every class 1-11 alone at every level 1-30 from
level 0, with the maximum hit points option off and on, then --iterations
random multiclass level sets from random lower old levels; each call starts
from its own srand seed and the result and the rand value after it must be
equal. Run 20261013-150011: 10,660 inputs, passed.

The signature changed. The original takes four stack arguments (`ret 0x10`
at 0x542FDD): CompleteCharacterAbilities' call (0x6129E5-0x6129EB) pushes
the CON byte, the sprite's m_derivedStats (edi = sprite + 0x920), a local
CDerivedStats whose class levels it zeroed (esp+0x64) and the CAIObjectType
(esp+0x18). Ours had three (no old stats) and returned 0. Now
`INT GetStartingHitPoints(const CAIObjectType& typeAI, CDerivedStats&
oldDStats, CDerivedStats& newDStats, BYTE nCON) const`; typeAI and nCON are
not read. For each class 1-11 (`cmp esi, 0xb; jle`) with a level in the new
stats it adds sub_542CB0(nClass, oldDStats, newDStats, 1, 1).

Fixture (rules/starting_hp): the original's CRuleTables is a zeroed 0x1B58
block with the five hit point tables filled (our parse of HPWAR, HPWIZ,
HPPRS, HPROG and HPMONK, extracted by oracle.py run, laid out as the
original's C2DArray as tables.cpp does), the CDerivedStats are zeroed blocks
with the class level bytes at 0x47, and g_pBaldurChitin (0x8CF6DC) points at
a zeroed block whose m_pObjectGame (0x1C54) points at a zeroed block holding
only m_cOptions.m_bMaxHP (0x448A). This last is a global the function reads
(sub_542B40 at 0x542C0E) and is set the way R10b builds members: a zeroed
block with only what is read; the runner restores .data before every case.
Ours gets the same through zeroed storage, and its g_pBaldurChitin is reset
to null when the case ends.

The world_entry scenario's fighter gets 9 hit points at the world checkpoint
in the original (10 from the d10, -1 from CON 9).
