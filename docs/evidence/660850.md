# 0x660850 CScreenSinglePlayer::EngineActivated

## Disassembly reading

- The exe: three SetResRef/RegisterFont pairs (REALMS, STONESML,
  TOOLFONT), CheckEnableCharacters, the vtable+0xf4 SetCursor(0, FALSE),
  CUIManager::InvalidateRect(NULL).
- The lobby arm: `in_ECX[0x117] == 1` is field_45C == 1; when field_138E
  is set the exe clears it and returns; otherwise it sprints "%s %i" with
  PARTY and 0, reads Party.ini, loops the six slots over
  CMultiplayerSettings::GetCharacterStatus, and when all are
  CHARSTATUS_NO_CHARACTER checks `in_ECX[0x111] == 0 || *(int
  *)(in_ECX[0x111] + 8) == 0` (GetTopPopup() == NULL) before
  SummonPopup(10) - ours ends at exactly that point.

## Notes

The fork adds a function static `s_autoNewGameCompleted` and an
Iwd2AutoLoad block that parses an autoload action, clamps m_nTopParty /
m_nParty, sets field_139E = 10 and calls OnDoneButtonClick - none of that
exists in the exe, which goes from the GetTopPopup test straight to
SummonPopup(10) and returns. His m_nLobbyMode rename (field_45C) lives in
CScreenSinglePlayer.h outside the owned files.
